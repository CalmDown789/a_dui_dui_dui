# 成员B工作：C-B v0.2 背压与缓冲回填（B-ARCH-10）

日期：2026-09-23。对象是当前 `b_core_real` 五层连续流 RTL，不包含 C 的输入 ROM、64-row 输出条带缓冲、UART，也不把逻辑容量当作目标器件 RAMB36 实测数。

## 七项答复

1. **最大连续背压周期 N**：RTL 不设置有限的 N 上限或超时计数器。只要 `rst_n` 保持有效，`out_valid && !out_ready` 时最终输出 token 保持，背压逐级传回输入。因此对 C 的协议约束为“可任意持续”，而不是给出一个会丢数据的固定 N。当前 MAC 平衡树流水版本已在 C 原始 `c_core` + 真实 B 核的小尺寸 XSim 中观测到连续 **16,111 拍**输出背压且逐字节一致；此数是测试覆盖下限，不是能力上限或形式证明。
2. **FIFO/Buffer 深度、位宽与容量**：见下表。四个层间 FIFO 均为 32 个完整 HWC token。窗口 FIFO 各为 4 个完整窗口 token，且前端另保留两个在途窗口的容量预约。相位行 bank 为两个 960×32-bit 存储体。
3. **满状态行为**：FIFO 满时 `in_ready=0`，可在同拍有 `out_ready` 消费时同时出入；窗口前端按 FIFO 占用加两级在途预约决定是否再接收 padding 像素。相位 bank 满时停止写入下一行。后处理的两个 slot 都占用时停止接收新 INT32 向量。
4. **计算暂停点**：最终 `out_ready=0` 会依次堵住相位行 bank、L5 后处理、L5 八相累加及 MAC 发射、L5 窗口、F45，再传过 L4→L1 各级及输入 `in_ready`。每级只在自己的 ready/valid 握手时推进数据、相位或坐标；已发射的 MAC partial sum 在弹性寄存级等待。
5. **是否可能丢数据**：按上述握手契约，设计不主动丢弃有效 token。`start` 只在 B `busy=0` 时接受；帧中复位会清空状态，应视为主动中止本帧。输入源必须在 `in_valid && !in_ready` 时保持 `in_valid` 和 `in_data`。
6. **向前传播机制**：`out_ready → PixelShuffle word/bank → L5 post → L5 accumulator/issue → window FIFO/line bank → F45 → ... → F12 → L1 input in_ready`。局部同步读与 MAC 弹性寄存级均在背压链内。
7. **恢复条件**：C 再次拉高 `out_ready` 后，PixelShuffle 成功握手释放相位 word/行 bank；各级已有 token 依序流出并释放容量，最终 `in_ready` 可恢复。无需重发 `start`，也不需丢弃或重算已接受的输入。

上述显式数据存储合计 **177,661 B（173.50 KiB）**，未计状态/地址寄存器、参数 ROM 的 3,344 B、BRAM 宽深取整与复制。实际 RAMB36/LUTRAM/FF 映射仍需在 `xc7a200tfbg484-2` 合并综合中确认，不得据此把原 44 块 B 侧预算或系统 271 块预算标为已实现。

### 行 bank 的物理块预估差异

当前 RTL 为 L1/L3/L5 每一行分别声明一个独立、每拍读取的数组。若 Vivado 对各数组使用 1024×36 RAMB36 模式且不跨数组合并，则 L1 为 `4×ceil(8/36)=4` 块，L3 为 `2×ceil(128/36)=8` 块，L5 为 `4×ceil(256/36)=32` 块；PixelShuffle 两个 960×32 同步读 bank 再占约 2 块，合计 **46 块预估**。原 v1.1 的 44 块没有包含这一版 RTL 的逐 bank 映射证据，不能直接沿用。综合可能采用不同宽深布局或把部分存储映射到 FF/LUTRAM，因此 46 也不是实测结论。

C ZIP 的原始报告实测其 stub 骨架已用 **192 RAMB36**，而非旧预算中的 187；C+B 合并后的物理块数、参数 bank 复制和 85% 门槛均应以 C 的目标综合/实现报告重新核对。

## 证据与限制

- 独立 B ROM 顶层：6×5 和 96×54 使用 A 已审计整数参数逐值 XSim 通过。
- C 的 `c_core` 接入真实 B 核：连续两帧 6×5，每帧 3 个输出条带，总计 240 个输出 uint8 字节逐字节匹配，`proto_err=overflow_err=0`；当前流水版本最长连续 `out_valid && !out_ready` 为 16,111 拍。
- C 原 ZIP 的 `b_core_if.v` 未向 `b_core_real` 传图像尺寸。本地联调只在**隔离仿真副本**中补了 `.IMG_W(IMG_W), .IMG_H(IMG_H), .STRIPE_H(STRIPE_H)`；C 源码未被修改。C 正式集成时必须加入这三个参数，并为真实 FSRCNN 单独生成期望值，不能直接复用 stub 的最近邻 scoreboard。
