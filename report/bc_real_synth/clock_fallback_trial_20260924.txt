150 MHz worst path
  L5 out_phase register -> L5 MAC DSP48E1 A input
  WNS -0.585 ns; data path 3.876 ns (logic 0.685 ns, route 3.191 ns)
  Route fraction 82.3%; phase net fanout 124.
  Therefore 150 MHz is not timing-closed on this implementation.

120 MHz worst path
  C input request address req_addr_q_reg[13]_rep__2 -> input ROM
  RAMB36E1 ADDRARDADDR[13]
  WNS +0.012 ns; data path 7.370 ns (logic 0.379 ns, route 6.991 ns)
  Route fraction 94.9%; address net fanout 22; zero logic levels.
  The overall route completed with all 71,535 routable nets and 0 routing
  errors, but 12 ps slack is only a marginal tool pass and gives no useful
  implementation margin. It is not an engineering signoff or a board-ready
  performance configuration.

The 120 MHz timing report also records 1,094 DRC warnings, primarily DSP
input/output pipelining advice, BRAM async-control checks, and the unresolved
uart_tx pin/IO-standard assignment. No bitstream was generated and no board
image was tested. The official 200 MHz target and source parameters remain
unchanged.

Third-party diagnosis
  Lowering the clock did not fix one stable path; it changed which physical
  path limits timing. At 150 MHz the distributed phase-to-DSP mux remained
  worst. At 120 MHz the input ROM address route became worst. The project
  therefore has at least two independent routing bottlenecks. Further clock
  reduction alone would hide them and would need acceptance criteria for
  throughput; the next useful work is physical localization of these control
  paths and a margin-based post-route check, with UART pins resolved before
  any bitstream can be called board-test ready.
