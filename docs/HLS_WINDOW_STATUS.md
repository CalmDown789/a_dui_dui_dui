# 流式 3×3 行缓存/窗口阶段记录

## 当前完成

- 两条 640 像素深度的行缓存，映射为 BRAM。
- 每拍接收一个 INT8 像素，维护三行、三列移位窗口。
- 当 `row>=2 && col>=2` 时输出一个完整 3×3 窗口。
- 运行时 `rows`、`cols` 通过 AXI4-Lite 传入，输入输出使用 HLS stream。

4×5 递增矩阵 C 仿真得到 6 个窗口，并逐元素核对通过：

`WINDOW3X3_HLS_TEST_PASS windows=6`

## HLS 综合结果

目标器件：`xc7z020-clg400-1`。自测时钟约束：10 ns。

| 指标 | 结果 |
|---|---:|
| 像素循环 II | 1 |
| 估算 Fmax | 147.85 MHz |
| BRAM_18K | 2 / 280 |
| DSP | 1 / 220 |
| FF | 653 / 106400 |
| LUT | 972 / 53200 |

报告中的 DSP 来自当前运行时循环控制综合结果，不是卷积乘法器；后续集成时再统一优化控制资源。

## 结论边界

- 当前模块只输出完整窗口，不生成边界像素窗口。
- 这不等于成员 B 已选择 valid padding。若最终使用 same padding，将在该模块前后加入补零与尺寸适配。
- 输出是 72 bit 的内部窗口流，最终不会作为板级外部 AXI 视频接口直接暴露。
- 10 ns 是成员 C 的候选验证条件，不代表成员 A 已确认系统时钟。
- 当前只验证单通道窗口；多通道调度将在网络级骨架中实现。
