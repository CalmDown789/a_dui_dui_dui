# ACX750 成员 A 接口与量化约定

## 网络接口

输入是 `960×540×1` 的 uint8 Y 图像，HWC 行优先并从左上角开始。输出是 `1920×1080×1` 的 uint8 Y 图像。网络依次执行 `5×5 Conv 1→16`、`1×1 Conv 16→8`、一层 `3×3 Conv 8→8`、`1×1 Conv 8→16`、`5×5 Conv 16→4` 和 PixelShuffle×2。前四个卷积后使用逐通道 PReLU，所有卷积都采用零填充并保持 540p 空间尺寸。

末层直接训练为稠密四相位子像素头，不是 9×9 stride=2 反卷积的权重重排。末层通道 0、1、2、3 分别写入 2×2 输出块的左上、右上、左下、右下。

## 定点格式

外部输入输出为 uint8，模型输入 scale 为 `1/255`、zero point 为 0。隐藏激活使用逐层对称 INT16，权重使用逐输出通道对称 INT8，偏置和卷积累加使用 INT32。PReLU 系数为逐通道 Q1.15，并在卷积累加结果上执行后再重量化。

所有舍入采用最近舍入且中点远离零。INT32 累加、INT16 激活和 uint8 输出均显式饱和。各层精确 scale、Q31 重量化乘数、形状和文件名以 `artifacts/quant/quant_params.json` 为唯一事实来源。

PReLU 的负半轴计算同样执行有符号最近舍入且中点远离零，不能用裸算术右移代替。对 `n = accumulator × alpha_q15`，实现应使用 `sign(n) × ((abs(n) + 2^14) >> 15)`，随后再执行 INT32 饱和和 Q31 重量化。

## 文件排布

权重顺序为 OIHW。`.bin` 使用小端原始二进制；`.mem` 每行一个二进制补码十六进制值；`.coe` 使用 radix 16。逐层激活和累加测试向量使用 HWC 行优先，manifest 记录 dtype、shape、CRC32 和 SHA-256。

## 全尺寸整数验收

最终逐字节验收必须使用 `artifacts/full_integer_golden/output_1920x1080_y_u8.bin`，不得使用 `artifacts/full_reference/ref_out_fp32.npy` 或 `ref_out_quant.npy` 冒充 RTL Golden。后两者只用于算法效果和量化损失分析。

输入 ROM 文件 `artifacts/full_integer_golden/input_rom_2p19_u8.mem` 为 ASCII 十六进制、每行一个 uint8。地址 `0..518399` 对应 960×540 Y 图像的 HWC 行优先字节；地址 `518400..524287` 固定为 `00`。卷积越界填充值同样固定为整数零。

RTL 输出必须恰好为 `2073600` 字节，并与权威输出逐字节相等。固定结果为 CRC32 `87d353f1`、SHA-256 `be8e576beea1632e6ee8257ba39a92c9c7950e9ae90b202bd240677e2d85504e`。完整的逐层形状、值域和摘要哈希见 `artifacts/full_integer_golden/manifest.json`。
