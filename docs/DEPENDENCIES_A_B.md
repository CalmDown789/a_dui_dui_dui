# 依赖 A / B 的事项清单（Dependency Register）

> **用途**：把 C 侧「已做 / 未做 / 等谁」一次性讲清，供 A、B、C 三方对齐排期，
> 避免把「等 B」误当成「C 没干」或把「C 已参数化」误当成「已闭合」。
>
> **基线**：`任务书 v3.2.2 修订执行版` + `成员B对C架构接口与资源预算确认_v1.0`
> **仓库**：`srtp/c_side`（C 侧）　**生成时点**：2026-09-23　**HEAD**：`8eb7926`
> **当前验证状态**：4 个 testbench 全 PASS；仅综合 0 ERROR / 0 CRITICAL WARNING
> （RAMB36 192/365 = 52.60%、DSP 0、WNS(synthesis) −0.153 ns）
>
> 图例：🟥 阻塞 C 的下一步　🟨 不阻塞但影响结论成立性　🟩 C 可自行推进

---

## 0. 结论速览

| 分类 | 项数 | 说明 |
|---|---|---|
| **等 B** | **11 项**（B-1 ~ B-11） | 其中 **B-1 / B-2 是硬阻塞**；其余为回填与核对 |
| **等 A** | **5 项**（A-1 ~ A-5） | 其中 **A-1 / A-2 是硬阻塞**（整链对拍、真实 ROM 内容） |
| **B/C 双向确认** | **4 项**（D-1 ~ D-4） | 门槛 7 的组成 |
| **C 侧自决** | **6 项**（C-1 ~ C-6） | 不依赖 A/B |
| **非阻塞遗留** | **4 项**（N-1 ~ N-4） | 已定性、故意不做 |

**一句话结论**：C 侧骨架的**全部可独立完成部分已闭环**（RTL / 4 个 TB / 断言层 /
脚本 / XDC / 仅综合取证）。**下一步的实质推进被 B-1（真实五层 RTL）与 A-1（全尺寸整数 Golden）阻塞**；
其余 9 项 B 依赖与 3 项 A 依赖都是「参数已备、回填即生效」的形态，不需要重新设计 C。

### 依赖链（主路径）

```
A-1 全尺寸整数 Golden ─┬─→ B-9 整链 bit-exact ─→ B-1 真实五层 RTL ─┐
                       │                                          │
A-2 真实输入 .mem ─────┼─→ C-3 implementation / 上板               ├─→ 整链验收 P0~P4
                       │                                          │
B-2 B-ARCH-10 背压七项 ┴─→ C18 定向 N 用例 ─────────────────────────┘
```

## 5. 真实 B 到位后的替换作业 SOP

```text
1. 取 B 交付件 → 校验 SHA-256（见 §8 风险 R-1）
2. 把 b_core_real.v（及 B 的子模块）加入 scripts/run_sim.tcl 与 scripts/synth_check.tcl 的显式文件列表
3. 核对 b_core_if.v 的例化端口名/位宽是否与 B 交付一致
      · 一致 → 只打开宏
      · 不一致 → 仅改 b_core_if.v 的例化（不动其它 C 模块）
4. 打开编译宏 `C_USE_B_REAL`（xvlog/xelab 与 synth_design 均需带上）
5. 跑 python scripts/gen_input_mem.py pattern-full      # 若 B 仿真需要 ROM 内容
6. vivado -mode batch -source scripts/run_sim.tcl        # 期望 4 个 TB 全 PASS
      · 若 out_ready 背压相关问题 → 回看 B-2 的七项参数，补 N 定向用例
      · 若 stripe_last/frame_last 位置不符 → proto_err 会先报，属接口语义分歧，回 §五.8 修订契约
7. vivado -mode batch -source scripts/synth_check.tcl    # 期望 0 ERROR / 0 CRITICAL WARNING
8. 记录合并后的 report/utilization_synth.rpt → 判 §五.13（2）二级闭合
9. 更新 docs/C_IMPLEMENTATION_STATUS.md 与本文档的状态列
```

**不需要改动的 C 侧模块**（替换 B 后仍复用）：
`c_config.vh` / `c_top.v` / `c_core.v` / `c_ctrl.v` / `input_rom.v` / `input_stream.v` /
`stripe_buffer.v` / `pingpong_buffer.v` / `output_stream.v` / `uart_tx.v` /
`readback_ctrl.v` / `c_protocol_assertions.v` / 全部 TB / 全部脚本 / XDC。
