# 2× Pixel Shuffle 流模块阶段记录

## 数据流

输入顺序：`low_row → low_col → 4 channels`。

输出顺序：2 倍放大后单通道图像的普通逐行 raster scan。

每个低分辨率像素的 4 个通道映射到 2×2 块。默认候选为：

| 位置 | 通道 |
|---|---:|
| 左上 | 0 |
| 右上 | 1 |
| 左下 | 2 |
| 右下 | 3 |

四个通道索引均由 AXI4-Lite 参数提供，因此可在不改 HLS 数据通路的情况下调整排列。

为了保持高分辨率输出的逐行顺序，模块边读入一行低分辨率数据边输出上半行，并用两块行缓存保存每个 2×2 块的下半部分，随后输出下半行。

## C 仿真

2×3×4 输入分别验证：

1. 标准映射 `{0,1,2,3}`；
2. 反向映射 `{3,2,1,0}`。

两种映射均逐像素通过：`PIXEL_SHUFFLE_TEST_PASS cases=2`。

## HLS 综合结果

目标器件：`xc7z020-clg400-1`。自测时钟约束：10 ns。

| 指标 | 结果 |
|---|---:|
| 上半行低分辨率像素 II | 4 |
| 下半行低分辨率像素 II | 2 |
| 估算 Fmax | 182.10 MHz |
| BRAM_18K | 2 / 280 |
| DSP | 0 / 220 |
| FF | 304 / 106400 |
| LUT | 704 / 53200 |

II=4 对应每个低分辨率像素从 8 bit AXI stream 顺序读取 4 个通道；若成员 A 最终采用更宽的流数据位宽，可进一步打包并提高吞吐。

## 结论边界

- 当前只验证重排与 raster 顺序，不包含末层卷积或最终显示接口。
- 默认 `{0,1,2,3}` 只是标准候选，最终需要与成员 B 的框架导出顺序比对。
- 外部流位宽与 DMA/VDMA 连接方式仍由成员 A 的 overlay 方案决定。
