# 已有 UART 回传路径的 PC 接收工具

`capture_raw_uart.py` 接收现有 UART TX 的无头 Y 字节，保存完整读取记录、逐帧文件和接收清单，供既有对拍和播放器使用。它不向板卡发送任何字节，不实现尚未确认的输入接口、帧头、CRC 或流控，不能代替任务书 A4 的完整双向协议适配。

## 来源和适用边界

共享仓库 C 提交 `910e60e85fca5c869c311289cc8586b8cfb8fdb3` 的 `c_top.v` 只有 UART TX，`readback_ctrl.v` 直接输出原始字节。历史 100 MHz 板测采用 921600 baud、8N1，输出长度 2,073,600 字节。来源：[C 板测记录](https://github.com/CalmDown789/a_dui_dui_dui/blob/910e60e85fca5c869c311289cc8586b8cfb8fdb3/report/c_board_100mhz/BOARD_TEST_REPORT_2026-09-24.md)。工具默认波特率来自这个已知路径；新 bitstream 使用不同设置时须按实际构建配置指定 `--baud`，不能据默认参数认定硬件兼容。

无帧头的通路无法从任意半帧恢复同步，不能验证线上帧号。采集者必须安排“PC 接收已打开，随后外部启动完整帧”，并确认 USB 串口 RTS/DTR 没有连接到会意外复位或误控制板卡的端口。脚本不触发复位，不发送启动命令，不清空缓冲区，不自动重试。若通路已经在连续发送，必须先用双方约定的外部方式恢复已知帧边界；不能靠删除前面的字节去匹配 Golden。

串口库在打开端口时可能因驱动产生 RTS/DTR 短暂跳变。脚本在打开前设置 RTS/DTR 为 false，关闭软硬件流控，但不能保证消除驱动行为；接线安全仍需操作者确认。[pySerial 官方接口说明](https://pyserial.readthedocs.io/en/latest/pyserial_api.html#serial.Serial.open)

## 使用命令

从成员 A 仓库根目录运行，或解压成对包后运行。安装串口依赖；列举端口只读取设备列表，不打开端口：

```powershell
python -m pip install pyserial==3.5
python scripts/capture_raw_uart.py --list-ports
```

旧权威帧对应 `single_authority_manifest.json`，不要把视频第 0 帧误认为旧权威图。源码仓库示例：

```powershell
python scripts/capture_raw_uart.py --manifest artifacts/authority_pair/single_authority_manifest.json --port COM7 --output-dir 'D:\Codex File\dialogue file\board_capture\old_authority_run_01' --boundary-confirmed --control-lines-safe
python scripts/compare_received_frames.py --manifest artifacts/authority_pair/single_authority_manifest.json --received-manifest 'D:\Codex File\dialogue file\board_capture\old_authority_run_01\received_manifest.json' --report 'D:\Codex File\dialogue file\board_capture\old_authority_run_01\comparison.json'
python scripts/export_pc_player.py --manifest artifacts/authority_pair/single_authority_manifest.json --received-manifest 'D:\Codex File\dialogue file\board_capture\old_authority_run_01\received_manifest.json' --output 'D:\Codex File\dialogue file\board_capture\old_authority_run_01\player.html'
```

`COM7` 只是示例，替换为本机实际端口。两个确认标志只在完成上述外部边界和接线核验后添加，不能为让命令运行而盲目勾选。缺少确认、参数不合法或目标目录已存在时，在打开设备前拒绝执行。所有输出保存在 D 盘指定目录；重跑须使用新目录。

成对 ZIP 的文件布局仍统一在 `artifacts/multiframe/`，解压后上述 `--manifest` 改用 `artifacts/multiframe/single_authority_manifest.json`。便携包不自带 pySerial，需按上文安装；离线比较和播放器导出仍只用标准库。

若板卡以后真的按视频顺序连续输出不同帧，可以选择 `artifacts/multiframe/manifest.json` 接收对应帧数。但当前 ROM 自动重复旧帧不等于 8 帧视频已经运行；这组采集必须逐帧对拍，重复旧图应 FAIL。

## 文件和异常行为

- `wire_rx.bin`：本次实际 `read()` 返回的所有字节，保持原顺序，包含观察到的额外尾字节。
- `arrival_....bin`：按参考清单声明的固定长度分帧。帧号由主机赋值，`protocol_frame_id_observed=false`，不是已验证线上 ID。
- `received_manifest.json`：记录文件哈希、完整/超时/错误状态、原始流哈希、实际读取次数及会话结束原因；线上 CRC 填 `NOT_CHECKED`。
- `unexpected_tail.bin`：在完成目标帧数后的有限观察窗口内保存额外字节，不裁剪或默默忽略。窗口外未读取的数据不属于本次证据。

默认单次读取最多 4096 字节，串口读超时 0.1 秒；支持短读。`--idle-timeout 30` 限制无数据等待，`--total-timeout 300` 限制目标载荷接收过程；完整帧后的 `--tail-watch 1` 秒单独检查尾部，尾数据最多保存 65536 字节后停止并报错。缺帧、截断、断连、取消时保留已收数据，不补零；发现异常后不在未知边界自动重试。

接收完整只表示目标长度已保存，不表示数值正确。随后对拍才能判定与 Golden 是否一致；一字节错误可以表现为“接收 COMPLETE，但对拍 FAIL”。超时、尾部额外字节或中断的会话对拍不得通过。

`first_byte_utc` 和 `last_byte_utc` 是 PC 收到首个/最后一个含载荷读取块时的时间，不是 UART 引脚逐位时间。相应 monotonic offset 用于主机计时，整个 session 包含等待和尾部观察。电脑接收耗时及播放速度都不能代替核心周期、stall 或持续帧率。

## 验证范围

`tests/test_raw_uart_capture.py` 检查短读、边界、无数据、各位置截断、持续数据总超时、额外字节、断连、取消、非法配置、既有目录保护及原始流哈希。`selftest_raw_uart_capture.py` 使用完整 2,073,600 字节旧权威 Golden 和 8 帧输出，模拟接收、生成清单，再运行同一对拍与播放器入口，包含正确、截断、额外字节及错字节用例。

这些用例使用软件读取器，不打开实际串口，时间戳也是模拟值。实体端口、USB 驱动和板卡仍需现场验证；本工具不因此标记 A4 或多帧板测通过。
