# 成员 A 8K 扩展软件评估

日期：2026-10-08。范围：验证冻结 R0 软件链在小规模原生 8K 亮度样本上的空间画质和 PC 处理时间；不改权重、量化参数或 4K Golden。

## 结论

已将 8K 评估从单一场景扩展为 Fraunhofer HHI 的四个 SDR 序列：BodeMuseum、NeptuneFountain2、QuadrigaTree、SubwayTree；每个序列评估帧 120、240、360、480，共 16 帧。每帧比较直接 Keys bicubic ×8 与冻结 R0 的分级路径：FSRCNN ×2 到 1080p，再连续 Keys ×2 到 4K、×2 到 8K。中心裁边 16 像素的 16 帧平均结果：整数 R0 为 **30.5313 dB / 0.877674 SSIM**，直接 ×8 双三次为 **29.6304 dB / 0.868571 SSIM**，差值 **+0.9009 dB / +0.009103 SSIM**；FP32 R0 为 30.5502 dB / 0.878949 SSIM。16 帧的整数 PSNR 均高于直接双三次，单帧增益约 **+0.64 至 +1.11 dB**。

这些仍是 16 帧、四个固定序列、固定合成降采样条件下的 A 侧 PC 软件结果。取样帧相隔 120 帧（2 秒），不是连续视频测试；不能外推为普遍 8K 画质收益、时间稳定性、8K 实时性能或 FPGA 结果。

## 数据与使用边界

源素材为 Fraunhofer HHI 8K Berlin SDR 序列。官方页列出七个 7680×4320、10-bit YCbCr 4:2:0、BT.2020 limited-range、60 fps、600 帧场景；本轮只选 BodeMuseum、NeptuneFountain2、QuadrigaTree、SubwayTree 四个序列。作者为 Björn Kowalewsky，版权归 Fraunhofer HHI，许可为 CC BY-NC-ND 4.0。来源与许可见 [Fraunhofer HHI 官方页面](https://www.hhi.fraunhofer.de/en/departments/vca/research-groups/video-coding-systems/8k-sequences.html)。

只按 HTTP Range 读取 16 个选定帧的 Y 平面，每帧 66,355,200 字节；没有下载任何完整 59.7 GB 序列。10-bit limited-range Y 按 `[64, 940] → [0, 255]` 转为 Y8，再用 FFmpeg bicubic 生成 960×540 合成输入。源平面、派生图像和逐帧 JSON 留在忽略的 `.data/` 目录，不提交仓库；本报告只发布聚合指标与序列/帧号，不附图像或视频。

## 评测口径

- 输入：960×540 full-range Y8；参考：同一帧的 7680×4320 full-range Y8。
- 直接基线：Keys bicubic ×8。
- 分级路径：冻结 `member-a-v1.0.1` d16/s8/m1/c16 R0，分别用 FP32 和正式整数参考产生 1080p，再进行 Keys ×2、×2。
- Keys 规则：`a=-0.5`、half-pixel 中心坐标、边缘复制、float64 可分离累加、中点远离零舍入、uint8 饱和。
- 指标：Y PSNR（峰值 255）与 11×11 高斯 SSIM（sigma=1.5）；全图和 shave-16 分开报告。
- 输出尺寸：7680×4320 Y8，即 33,177,600 字节。评估脚本不保存候选输出图，只写摘要指标、时间和哈希。

## 结果

中心裁边 16 像素的均值（Y PSNR dB / SSIM）：

| 序列（每序列 4 帧） | 直接 bicubic ×8 | R0 整数分级 | 整数增益 |
|---|---:|---:|---:|
| BodeMuseum | 27.5765 / 0.818702 | 28.2227 / 0.826757 | +0.6462 / +0.008054 |
| NeptuneFountain2 | 33.9982 / 0.924976 | 35.0112 / 0.929279 | +1.0130 / +0.004303 |
| QuadrigaTree | 28.5253 / 0.852645 | 29.6076 / 0.868446 | +1.0822 / +0.015801 |
| SubwayTree | 28.4215 / 0.877962 | 29.2836 / 0.886217 | +0.8621 / +0.008255 |
| **16 帧等权平均** | **29.6304 / 0.868571** | **30.5313 / 0.877674** | **+0.9009 / +0.009103** |

16 帧整体的 R0 FP32 shave-16 均值为 30.5502 dB / 0.878949 SSIM。由于四个序列各取四帧，整体均值与逐序列均值采用相同权重；逐帧精确值、SHA 和运行时间保存在本机 `.data/member_a_task_20261008/hhi_8k_multisequence/aggregate_8k_16frames_verified.json`，可用汇总校验脚本核对。

同机软件路径中位数：直接 bicubic ×8 为 820.5 ms；FP32 路径的 CNN、1080p→4K 和 4K→8K 分别为 156.2、353.8、1,751.0 ms；整数参考对应为 1,584.5、338.4、1,711.9 ms。FP32 CNN 使用 RTX 5060 Laptop GPU，整数参考和 Keys 插值在 CPU。计时不代表持续吞吐或 ACX750 性能。

## 复现

以下示例只取选定帧的亮度平面，逐帧输入和 JSON 输出均写入忽略目录：

```powershell
$root = ".data\member_a_task_20261008\hhi_8k_multisequence"
$reports = @()
$frameReports = @()
foreach ($sequence in @("BodeMuseum", "NeptuneFountain2", "QuadrigaTree", "SubwayTree")) {
  foreach ($frame in @(120, 240, 360, 480)) {
    $dir = "$root\prepared_${sequence}_$frame"
    $stem = "{0}_frame_{1:D3}" -f $sequence, $frame
    python scripts\prepare_member_a_8k_hhi_frame.py `
      --download-official --sequence $sequence --frame-index $frame --output-dir $dir
    $report = "$root\evaluation_${sequence}_$frame.json"
    python scripts\evaluate_member_a_8k.py `
      --hr-y8 "$dir\${stem}_7680x4320_y8.bin" `
      --lr-y8 "$dir\${stem}_960x540_y8.bin" `
      --preparation-manifest "$dir\preparation_manifest.json" `
      --output $report --device auto
    $reports += @("--report", $report)
    $frameReports += @("--frame-report", $report)
  }
}
python scripts\summarize_member_a_8k.py @reports --output "$root\aggregate_8k_16frames_verified.json"
python scripts\verify_member_a_8k_multisequence_summary.py `
  --summary "$root\aggregate_8k_16frames_verified.json" @frameReports
```

正式模型与参数哈希记录在逐帧 JSON 中。脚本拒绝把源素材、派生图像或汇总报告写出 `.data/`。这次扩展补足了多场景软件质量对照，但连续视频、更多场景、整机预览和板端 8K 时序仍未验收。
