# 成员 A 8K 扩展软件评估

日期：2026-10-08。范围：验证冻结 R0 软件链在小规模原生 8K 亮度样本上的空间画质和 PC 处理时间；不改权重、量化参数或 4K Golden。

## 结论

已在 Fraunhofer HHI 的 BodeMuseum SDR 序列上评估 120、240、360、480 四帧。每帧比较直接 Keys bicubic ×8 与两种冻结 R0 分级路径：FSRCNN ×2 到 1080p，再连续 Keys ×2 到 4K、×2 到 8K。四帧中心裁边 16 像素的平均结果：R0 整数路径为 **28.2227 dB / 0.826757 SSIM**，高于直接 ×8 双三次的 **27.5765 dB / 0.818702**，差值为 **+0.6462 dB / +0.008054 SSIM**。FP32 路径差值为 **+0.6593 dB / +0.009633 SSIM**。

这是 4 帧、单一序列、固定合成降采样条件下的 A 侧 PC 软件结果，不能外推为普遍 8K 画质收益、连续视频效果、8K 实时性能或 FPGA 结果。

## 数据与使用边界

源素材为 Fraunhofer HHI 的 BodeMuseum SDR 原生 7680×4320 序列，页面列明 10-bit YCbCr 4:2:0、BT.2020、limited range、60 fps、600 帧。作者为 Björn Kowalewsky，版权归 Fraunhofer HHI；序列采用 CC BY-NC-ND 4.0。来源及许可见 [Fraunhofer HHI 8K Berlin Test Sequences](https://www.hhi.fraunhofer.de/en/departments/vca/research-groups/video-coding-systems/8k-sequences.html)。

只按 HTTP Range 读取所选四帧的 Y 平面；未下载整段 59.7 GB 序列。10-bit limited-range Y 按 `[64, 940] → [0, 255]` 转为 Y8，再由 FFmpeg bicubic 生成 960×540 合成输入。源平面、派生图像和逐帧 JSON 保留在忽略的 `.data/` 目录，不提交仓库；报告只发布聚合指标、帧编号及 SHA-256，不附图像或视频。

## 评测口径

- 输入：960×540 full-range Y8；参考：同一帧的 7680×4320 full-range Y8。
- 直接基线：Keys bicubic ×8。
- 分级路径：冻结 `member-a-v1.0.1` d16/s8/m1/c16 R0，分别用 FP32 和正式整数参考产生 1080p，再进行 Keys ×2、×2。
- Keys 规则：`a=-0.5`、half-pixel 中心坐标、边缘复制、float64 可分离累加、中点远离零舍入、uint8 饱和。
- 指标：Y PSNR（峰值 255）与 11×11 高斯 SSIM（sigma=1.5）；全图和 shave-16 分开报告。
- 输出尺寸：7680×4320 Y8，即 33,177,600 字节。评估脚本不保存候选输出图，只写摘要指标、时间和哈希。

## 结果

中心裁边 16 像素的逐帧 PSNR（dB）：

| HHI 帧号 | 直接 bicubic ×8 | R0 FP32 分级 | R0 整数分级 |
|---:|---:|---:|---:|
| 120 | 27.5239 | 28.1782 | 28.1652 |
| 240 | 27.5462 | 28.2019 | 28.1888 |
| 360 | 27.5922 | 28.2578 | 28.2443 |
| 480 | 27.6437 | 28.3052 | 28.2923 |
| 平均 | 27.5765 | 28.2358 | 28.2227 |

四帧 shave-16 SSIM 平均：直接 bicubic ×8 为 0.818702，R0 FP32 分级为 0.828335，R0 整数分级为 0.826757。全图平均 PSNR 分别为 27.6088、28.2673、28.2540 dB；全图平均 SSIM 分别为 0.819486、0.829055、0.827480。

同机单次处理时间中位数仅用于软件流程比较：直接 bicubic ×8 为 863.1 ms；FP32 路径的 CNN、1080p→4K 和 4K→8K 中位数分别为 162.5、369.5、1,800.7 ms；整数参考对应为 1,684.2、359.5、1,795.3 ms。FP32 CNN 用 RTX 5060 Laptop GPU，整数参考和 Keys 插值在 CPU。单次计时不等于稳定吞吐率；这些数字不代表 ACX750 性能。

## 复现

以下示例只取选定帧的亮度平面，逐帧输入和 JSON 输出均写入忽略目录：

```powershell
$root = ".data\member_a_task_20261008\hhi_8k_sample"
foreach ($frame in @(120, 240, 360, 480)) {
  $dir = "$root\prepared_frame$frame"
  python scripts\prepare_member_a_8k_hhi_frame.py `
    --download-official --frame-index $frame --output-dir $dir
  python scripts\evaluate_member_a_8k.py `
    --hr-y8 "$dir\BodeMuseum_frame_${frame}_7680x4320_y8.bin" `
    --lr-y8 "$dir\BodeMuseum_frame_${frame}_960x540_y8.bin" `
    --preparation-manifest "$dir\preparation_manifest.json" `
    --output "$root\evaluation_8k_frame$frame.json" --device auto
}
python scripts\summarize_member_a_8k.py `
  --report "$root\evaluation_8k_frame120.json" `
  --report "$root\evaluation_8k_frame240.json" `
  --report "$root\evaluation_8k_frame360.json" `
  --report "$root\evaluation_8k_frame480.json" `
  --output "$root\aggregate_8k_4frames.json"
```

正式模型与参数哈希记录在逐帧 JSON 中。脚本拒绝把派生源帧或汇总报告写出 `.data/`。当前结论仅完成 A08 的一项小规模 8K 软件评估；更多序列、连续视频、整机预览和板端时序仍未验收。
