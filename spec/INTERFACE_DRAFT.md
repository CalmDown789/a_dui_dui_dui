## AXI4-Stream 草案

顶层暂定两个流端口：`s_axis_video` 和 `m_axis_video`。数据宽度先保持可配置，默认每拍承载一个 8 bit Y 像素。

以下内容不在成员 C 内部单方面冻结：

- 采用 AXI DMA、AXI VDMA 或视频流直连；
- `TLAST` 表示行尾还是帧尾；
- 是否使用 `TUSER[0]` 表示帧首；
- 系统时钟频率。

这些项目由成员 A 结合 overlay 方案确认。确认前，HLS 顶层通过类型与编译参数隔离 sideband 语义。

## AXI4-Lite 草案

建议保留如下控制含义，具体地址由 HLS 导出后与成员 A 的 Block Design 地址规划共同冻结：

| 字段 | 用途 | 状态 |
|---|---|---|
| `ap_start` | 启动一帧 | HLS 标准控制 |
| `ap_done` | 一帧处理完成 | HLS 标准控制 |
| `ap_idle` | IP 空闲 | HLS 标准控制 |
| `ap_ready` | 可接受下一次启动 | HLS 标准控制 |
| `rows` | 输入高度，正式值 360 | C 内部可配置 |
| `cols` | 输入宽度，正式值 640 | C 内部可配置 |
| `status/error` | 超时或尺寸错误状态 | 待实现 |

## 数值规则待成员 B 确认

- same padding 或 valid padding；
- 对称/非对称量化及零点；
- 每层 scale、requantize 舍入方式和饱和方式；
- PReLU 斜率格式；
- 权重顺序和测试向量格式。

成员 C 在确认前只使用可替换的 `requantize()` 与 `prelu()` 占位接口，不把自测规则当作最终模型规则。
